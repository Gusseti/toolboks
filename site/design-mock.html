Verified means Toolboks checked it. Not the add-on.

First-party add-ons carry the verified seal. The list of approved packages is built into the app, so a package can't give itself the seal, and a changed manifest loses it.

Built-in allowlist
Toolboks recognizes the exact approved packages. Verification isn't a flag a package can set.
Access, up front
Every install and update lists what the add-on can reach, before you say yes.
Shown first
Verified add-ons sit at the top of the browser.
Yours to undo
Turn any add-on off, or remove it with its saved settings.

Write a manifest. Get a tool that belongs.

An add-on describes its pages; Toolboks draws them in its own look. No palette, fonts or icons to bring. Validate and pack with the SDK, then drop the file on the window.

{ "manifest": { "id": "com.example.hello-system", "title": "Hello System", "capabilities": ["host_metrics", "local_preferences"] }, "pages": [{ "title": "Overview", "widgets": [ { "kind": "heading", "text": "Your system at a glance" }, { "kind": "metric", "binding": "memory_percent" }, { "kind": "metric", "binding": "uptime" } ] }] }
